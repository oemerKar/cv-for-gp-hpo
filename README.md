# Evaluating Cross-Validation for Gaussian Process Hyperparameter Optimization in Bayesian Optimization
Code accompanying the Bachelor's Thesis *"Evaluating Cross-Validation for Gaussian Process Hyperparameter Optimization in Bayesian Optimization"*. It compares three methods for GP hyperparmeter optimization in Bayesian Optimization Loops, marginal Likelihood (MLL), Leave-one-out-cross-validation (LOOCV) and MCMC on synthetic, self generated and real-world test functions.
The methods are compared regarding metrics such as performance, robustness and convergence.

## Overview
There are two main Pipelines, sharing the same core, but being independent otherwise:

### Pipeline A: BBOB/GP Sampled- Synthetic Test functions
Runs the three methods on the BBOB test functions and GP-sampled functions (via RFF). These experiments are orchestrated directly by `run_experiments.py`, results land in `functions/experiments/`.

### Pipeline B: CARPS - Real-World Benchmarks
Runs the three methods on real benchmark tasks (BBOB, HPOBench, YAHPO) through the CARPS Framework by `run_carps_experiments.py` + `carps_wrapper.py`, results land in `functions/results/` (not committed) and are summarized in `functions/combined_logs_10.csv`.

Both pipelines implement MLL/LOOCV/MCMC fitting independently. Pipeline A as functions in `functions/loops.py`, Pipeline B as Optimizer subclasses in `functions/carps_wrapper.py` that use CARPS' ask/tell interface.

## Running an experiment

All commands below are run from inside `functions/` (`cd functions`) — the scripts use relative
paths (`experiments/`, `results/`, ...) for their output, so running them from the repo root
instead would write those folders one level up from where this README shows them.

**Pipeline A**, single run:
```bash
python run_experiments.py --experiment experiment_one --seed 0
```
Aggregate all seeds for an experiment into a summary table + regret plot (once all seeds have run):
```bash
python run_experiments.py --experiment experiment_one
```
On the cluster: `sbatch submit.sh` submits the array job (and the dependent aggregation
job) for every experiment.

**Pipeline B**, single run and all all BBOB Tasks:
```bash
python run_carps_experiments.py --local            # all non-BBOB tasks, serial
python run_carps_experiments.py --array-index 0    # a single grid entry (SLURM style)
```
On the cluster: `sbatch submit_carps_experiment.sh` (HPOBench/YAHPO, `carps-env`) and
`sbatch submit_carps_bbob_experiments.sh` (BBOB, `carps-bbob-env`).

Post-processing, in `carps-bbob-env`:
```bash
python gather_results.py --results-dir results --out combined_logs.csv
python carps_analyze.py --combined-logs combined_logs.csv --out autorank_matrix.csv
```

Cluster paths (`/work/...`, `/home/...`) in the `.sh` scripts are Cluster-specific and need to be
adjusted to the own paths.

## `BO_Loop.ipynb`
The central analysis notebook (imports functions.*), organized into four sections:
1. **Preliminary Experiments / Main Experiments (deprecated)**: exploratory work that led to the exclusion of K-Fold CV and old versions of the main experiments that were later outsourced to `run_experiments.py`. Kept for context but marked as outdated.
2. **Analysis**: Analysis of the results of the main experiments generated by `run_experiments.py`. Produces plots and tables for the Experiment chapter of the thesis and does significance testing, sensitivity analysis, and the CARPS analysis.
3. **Appendix** Generates the grid plots used in the Appendix of the thesis by combining the plots made in the Analysis 


## Known limitations

- The EA/CMA-ES-based cross-validation alternative (`bo_loop_ea` and helpers in `loops.py`) was
  tried during the exploratory phase and discarded: worse regret and worse runtime than
  LOOCV/MLL, so not part of the final experiments. Kept in the code (and exercised in the
  notebook's early cells) to document.
- AI-generated functions where used and are marked by a `#AI GENERATED` comment above the method
